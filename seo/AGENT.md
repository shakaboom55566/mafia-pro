# SEO-агент Mafia Pro — инструкция

Еженедельная задача (scheduled task «Mafia Pro: SEO-агент», понедельник утром по Киеву). Цель — вывести сайт
(`seo/build-site.mjs`, 5 языков: ru, uk, en, pl, hy) на первую страницу Google по запросам из `seo/keywords.json`
и по тем, что найдёт Search Console. Работает только с сайтом; приложение, бэкенд, бот, Discord — не трогает.

## Каждый запуск
1. Репозиторий `shakaboom55566/mafia-pro`: `git fetch origin main`, работать от свежего main. Параллельные сессии пушат в main — перед пушем rebase.
2. Данные: если `seo/reports/latest.md` старше 2 дней — запустить отчёт через REST (GraphQL из сессий недоступен, `gh workflow run` не работает): `gh api -X POST repos/shakaboom55566/mafia-pro/actions/workflows/seo-report.yml/dispatches -f ref=main`, ждать, пока `gh api "repos/shakaboom55566/mafia-pro/actions/workflows/seo-report.yml/runs?per_page=1" -q '.workflow_runs[0].status'` станет `completed` (3–6 мин), затем `git pull`.
   Прочитать `seo/reports/latest.md`, свежий `seo/reports/<дата>.json`, `seo/journal.md`, `seo/keywords.json`, `seo/overrides.json`.
3. Решить, что улучшить — **не больше 5 правок за запуск**, по приоритету:
   1. Техника: живые проверки с ошибками, ключевые страницы не в индексе, «canonical не совпадает», PageSpeed SEO < 90 или скорость < 80 — найти причину и исправить в `seo/`.
   2. Первая страница, но CTR < 2 % (`lowCtr`) — переписать title/description этой страницы в `seo/overrides.json`: запрос в начале title, выгода и призыв в description.
   3. Вторая страница, позиции 8–20 (`striking`) — усилить страницу: `intro` (абзац под запрос) и/или `faq` (2–4 вопроса, как люди спрашивают). Факты — только из приложения: правила ролей, порядок ночи, составы (`node -e` через `loadApp` из `discord/setup.mjs`) или `src/02*.js`. Ничего не выдумывать.
   4. Новые запросы с показами, которых нет в `keywords.json`, — добавить (язык, страница, уровень).
   5. Запросы, для которых нет подходящей страницы (например «мафия для детей», «мафия на свадьбу»), — не создавать разделы самому, а предложить владельцу в итоге (страница, запросы, показы).
4. Не трогать страницу, которую меняли меньше 21 дня назад (смотреть `seo/journal.md`) — Google нужно время, иначе не понять, что сработало. Исключение — техническая ошибка.
5. Проверить: `node seo/test-site.mjs` (уникальные title/description, ссылки, JSON-LD) и `node seo/test-report.mjs`. Title ≤ 60 символов, description ≤ 155.
6. Коммит `seo: <что сделано>` (подпись Co-Authored-By как обычно), `git fetch origin main && git rebase origin/main`, push. Через 4–6 минут проверить комментарий workflow «Deploy to GitHub Pages» к коммиту (`gh api repos/shakaboom55566/mafia-pro/commits/<sha>/comments`).
7. Дописать в `seo/journal.md` строку на каждую правку: дата · страница · что изменено · ради какого запроса · позиция/показы/CTR до. Отдельным коммитом с данными (`seo/journal.md` не запускает деплой).
8. Итог владельцу — push-уведомлением, коротко по-русски: показы и клики по языкам и динамика, сколько страниц в индексе, что изменено, что нужно от владельца.

WebSearch по брендовым запросам («Mafia Pro мафия», «mafiaprof_bot») — появился ли сайт; правки контента только по явным пробелам.
В итоге одной строкой напомнить, чего не хватает: секреты `GSC_SA_KEY` и `GSC_PROPERTY` (инструкция — `claude/seo.md` в проекте и README).
