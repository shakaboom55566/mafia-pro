# Рекламный агент Mafia Pro — Meta (Instagram + Facebook), Днепр

Ежедневная задача (scheduled task «Mafia Pro: реклама Meta», 09:20 по Киеву). Механику (замены каждые 6 дневных часов, отчёты) делает workflow «Ads» сам каждый час. **Твоя работа — чтобы было чем заменять и чтобы замены становились лучше:** прочитать цифры, понять, что работает, дописать новые брифы в очередь, записать выводы. Правила содержания — `ads/PLAN.md` (прочитай целиком каждый запуск). Меняешь только `ads/creatives/`, `ads/journal.md` и, по правилу ниже, `ads/config.json` — никакого кода, workflow, бэкенда, сайта.

REST вместо GraphQL: только `gh api`. Репозиторий: `shakaboom55566/mafia-pro`.

## 1. Готовность

```
gh api -X POST repos/shakaboom55566/mafia-pro/actions/workflows/ads.yml/dispatches -f ref=main -f 'inputs[mode]=status'
gh api "repos/shakaboom55566/mafia-pro/actions/workflows/ads.yml/runs?per_page=1" -q '.workflow_runs[0] | .status + " " + .head_sha'   # ждать completed (~1 мин)
gh api repos/shakaboom55566/mafia-pro/commits/<head_sha>/comments -q '[.[] | select(.body | startswith("**Ads** (status)"))][-1].body'
```

- `ready: yes` → дальше.
- `not ready` / `problem: …` → брифы всё равно держи в очереди (6–8 штук), итог владельцу — что именно осталось сделать (по строкам статуса: ключи `META_ADS_TOKEN`, `META_AD_ACCOUNT_ID`, `META_PAGE_ID` или /social, `META_PIXEL_ID`, `GEMINI_API_KEY`; лимит расходов кабинета; статус кабинета). Если секреты есть (`gh secret list -R shakaboom55566/mafia-pro`), а статус пишет `Conversions API off` — один раз перезапусти деплой бэкенда: `gh api -X POST repos/shakaboom55566/mafia-pro/actions/workflows/backend.yml/dispatches -f ref=main`.
- `LOCKDOWN` или `PAUSED in /ads` → ничего не меняешь, итог одной строкой.

## 2. Цифры

```
gh api -X POST repos/shakaboom55566/mafia-pro/actions/workflows/ads.yml/dispatches -f ref=main -f 'inputs[mode]=stats'
```
Тот же способ ждать и читать `**Ads** (stats)`. Там каждое объявление: бриф, вид, `hook`, `angle`, статус, дневные часы, показы, досмотр 3 с, CTR, переходы, цена перехода, расход, новые игроки, сыграли, вердикт и причины; ниже — последние замены.

Допиши в `ads/journal.md` (без личных данных) 3–6 строк: дата · день теста N из 15 · расход и цена нового игрока · лучшее и худшее объявление и почему · какие `hook`/`angle`/вид выигрывают · что меняешь в очереди. Выводы — по объявлениям с ≥ 1000 показов; одно объявление — не закономерность.

## 3. Очередь брифов

1. Сколько неиспользованных брифов `dnp` (те, чьих id нет в `ads/state/dnp.json` → `used`). Цель — **6–8**.
2. Допиши недостающие по `ads/PLAN.md`, номера по порядку (`dnp-009`, …). Правила подбора:
   - больше вариантов **того, что выигрывает** (тот же `hook` и `angle`, новая сцена и новый текст), но не больше половины очереди одного типа;
   - 1–2 брифа — **новые проверки** (`hook` или `angle`, которых ещё не было или мало);
   - проигравшее дважды — не повторяй неделю;
   - видео и картинки — по цифрам: если картинки дают переход вдвое дешевле — больше картинок (они дешевле и в Gemini);
   - первые ~125 символов текста — главное.
3. `node ads/run.mjs briefs` — без ошибок.
4. Коммит `ads: briefs dnp-NNN…NNN, journal` → `git fetch origin main && git rebase origin/main && git push origin HEAD:main`. Workflow проверит брифы сам; запускать их не нужно — возьмёт ежечасная проверка.

## 4. Бюджет и сроки (только по данным, редко)

- Не трогай бюджет, сроки и географию без слов владельца. `ads/config.json` меняешь только если владелец написал (например, «добавь Украину», «ещё неделя»), — тогда создай новую кампанию в `campaigns` (новый `tag`, своя страница в `ads/landing.mjs` и тег в `backend/src/ads.js` SOURCES — это уже код: сделай отдельной сессией, не в этой задаче) или продли `days`.
- После 15-го дня workflow сам пришлёт итог. В этот день в журнале — итоговый вывод по правилу из `ads/PLAN.md`; новые брифы не пишешь, пока владелец не решит продолжать.
