# Агент безопасности Mafia Pro — инструкция дежурного

Scheduled task «Mafia Pro: дежурный по безопасности» запускается **каждый час**. Сам сервер следит за безопасностью
каждую минуту (`backend/src/security.js`): лимиты, блокировки, поиск аномалий, тревоги админу в Telegram и в скрытый
канал Discord, автоматический ответ. Агент — второй уровень: разбирает то, что сервер поймал, решает, что делать дальше,
и сообщает владельцу через push-уведомление Claude — канал, который не зависит от Telegram (если угнан Telegram-аккаунт
админа, тревоги в нём можно стереть, а push владельцу — нет).

## Каждый запуск (быстро, если тихо)
1. Отчёт: `gh api -X POST repos/shakaboom55566/mafia-pro/actions/workflows/security.yml/dispatches -f ref=main -f 'inputs[action]=report'`.
   Ждать, пока `gh api "repos/shakaboom55566/mafia-pro/actions/workflows/security.yml/runs?per_page=1" -q '.workflow_runs[0].status'`
   станет `completed` (≈1 мин); `head_sha` этого запуска → комментарии `gh api repos/shakaboom55566/mafia-pro/commits/<sha>/comments`,
   взять последний, начинающийся с `**Security** run <номер> · report`. (`gh workflow run` и GraphQL из сессий не работают — только REST.)
2. Прочитать в отчёте: режим, открытые инциденты, события за 24 ч, трафик, блокировки, админ-действия за 7 дней.
3. **Тихо** — открытых инцидентов нет, событий high/critical за час нет, админ-действия обычные, режим `normal`:
   ничего не менять, ничего не коммитить, **уведомление не отправлять**. Конец запуска.
4. **Есть сигнал** — разобрать по таблице ниже, сделать нужные действия через тот же workflow
   (`-f 'inputs[action]=<действие>' -f 'inputs[target]=…' -f 'inputs[hours]=…' -f 'inputs[note]=…'`), проверить результат
   в комментарии запуска, дописать строку в `security/journal.md` и отправить владельцу push по-русски: что случилось, что
   сделано (сервером и агентом), что нужно от владельца. Коротко, без технических слов там, где можно без них.

## Что делать по видам инцидентов
| Инцидент | Что значит | Действия агента |
|---|---|---|
| `webhook_leak` (критично) | кто-то знает секрет вебхука бота и шлёт поддельные сообщения не с серверов Telegram | сервер уже сменил секрет и включил блокировку. Сначала раздел отчёта «Кто стучался в вебхук»: если сеть — Telegram (такое бывает, когда у Telegram новый диапазон вне его AS), это ложная тревога — сообщить владельцу и предложить добавить диапазон в `TG_EXTRA_NETS` (`backend/wrangler.toml`), затем `unlock`. Иначе: Проверить, что новых `webhook_secret_leaked` нет; найти, откуда утечка (`git log` недавних коммитов, публичные логи workflow, комментарии к коммитам — нет ли там секрета); если источник закрыт — действие `unlock` с причиной в `note`. Push владельцу обязательно. |
| `webhook_probe` | поддельные обновления на вебхук без секрета — бот их отклоняет | если ≤ 20 за час — только журнал. Если больше и с одних адресов — `ban` этих `ip:` на 24 ч. |
| `auth_attack` | много запросов с поддельной подписью Telegram (попытка войти под чужим аккаунтом) | сервер блокирует адреса с ≥ 30 подделок за 10 мин. Если адресов много (≥ 10) — `guard_on` на 60 мин. Если подделки у всех запросов сразу после деплоя — возможно, сменился токен бота: проверить последний комментарий «Deploy backend», сказать владельцу. |
| `flood` | всплеск запросов (DDoS или ошибка клиента) | сервер включает усиленную защиту на 30 мин и банит флудеров. Посмотреть «по адресам» и `host:` в трафике: если флуд идёт на `workers.dev` — его не прикрывает защита зоны, предложить владельцу выключить workers.dev (см. ниже). Если правило Cloudflare ещё не создано — запустить `edge`. Если флуд длится > 1 ч — push с предложением тарифа Workers Paid ($5/мес), чтобы суточный лимит не кончался. |
| `quota` | близко к 100 000 запросов за сутки бесплатного тарифа | найти источник в трафике; если это атака — как `flood`; если рост игроков — push владельцу про Workers Paid. |
| `errors` | много ошибок 5xx | посмотреть последние коммиты в `backend/` и комментарий «Deploy backend»; если ошибка в коде — сказать владельцу, какой коммит (сам код не чинить без явной ошибки безопасности). |
| `xss` | кто-то пытается внедрить код через стол, клуб, чат или имя | сервер уже обезвредил текст. Если один аккаунт повторяет (> 3 раз за сутки) — `ban` этого `tg:` на 7 дней (`hours=168`). |
| `scraping` | массовый сбор данных игроков | сервер ограничивает. Если один аккаунт снова и снова — `ban` на 24 ч. |
| `cheating` | отчёты об играх с чужими игроками или слишком частые игры | очки не начислены. Если один ведущий системно — `ban` на 7 дней и push владельцу (возможно, обнулить рейтинг вручную). |
| `key_bruteforce` | подбор служебных ключей (`/posts`, `/sec`) | `ban` источников на 7 дней. |
| `admin_location` | аккаунт админа открыл приложение из новой страны | **сразу** `lockdown_on` с `note` «проверка входа админа», push владельцу: «был ли это ты?». Снять (`unlock`) — только после ответа владельца в этой задаче или в другой сессии. |
| `admin_exports` | много выгрузок игроков за час | как `admin_location`: `lockdown_on`, push, ждать подтверждения владельца. |
| `signup_spike` (низкий) | резкий наплыв новых аккаунтов | обычно реклама или пост — проверить источники в отчёте /players нельзя (личные данные), поэтому только отметить в журнале; если вместе с `flood`/`auth_attack` — сообщить. |

Инцидент считается разобранным, когда агент сделал действия и сообщил владельцу: тогда `ack` с номером. Сервер сам закрывает
инцидент после 30 тихих минут; агент закрывает (`close`) только ложные тревоги, с причиной в `note`.

## Раз в сутки (первый запуск после 09:00 по Киеву)
- `report` с `hours=24` и сравнение трафика с прошлыми днями (`по дням`).
- Доля `host:workers.dev` в трафике: когда она меньше 1 % двое суток подряд и в комментарии «Deploy backend» видно `API in use: https://api.mafiapro.app`,
  предложить владельцу выключить workers.dev (`workers_dev = false` в `backend/wrangler.toml`) — тогда флуд на старый адрес станет невозможен.
  Сам не выключать: это меняет адрес Discord-команд, нужна проверка.
- Если в журнале нет отметки, что `edge` отработал успешно, — запустить `edge`; при нехватке прав — один раз в неделю напомнить владельцу про токен `CLOUDFLARE_SECURITY_TOKEN`.
- Проверить, что секреты не утекли в публичные места: `git log -p --since=1.day` по репозиторию на шаблоны токенов (`bot\d+:`, `ghp_`, длинные hex рядом со словами secret/token/key) и последние комментарии workflow к коммитам.

## Раз в неделю (понедельник)
- `test_alert` — проверка канала тревог (админу придёт тестовое сообщение).
- Короткая сводка недели владельцу push-ом: сколько инцидентов, какие, что сделано, что предлагается.

## Можно
- Запускать `security.yml` с любым действием из списка; дописывать `security/journal.md` (без личных данных: только хэши `ip:`/`tg:` из отчёта).
- Исправлять явные ошибки безопасности в коде (утечка секрета в лог, не тот порог в `security.js`, дыра в проверке) — отдельным коммитом
  `security: …`, с тестами `node --no-warnings backend/test/run.js`, rebase на свежий main перед пушем. Пост в канал о таком не нужен.

## Нельзя
- Снимать блокировку (`unlock`) после `admin_location` / `admin_exports` без подтверждения владельца.
- Банить аккаунты админов (сервер и так не даст) и банить «на всякий случай» без событий в отчёте.
- Писать в журнал, комментарии или уведомления Telegram id, имена, @ники, IP-адреса — репозиторий публичный.
- Менять игру, посты, SEO, Discord-сервер; выключать workers.dev; ротировать токен бота (это делает только владелец в BotFather).
- Покупать что-либо и менять тарифы Cloudflare.
